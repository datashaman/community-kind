# Domain docs

This is a single-context repository.

## Before exploring

- Read root `CONTEXT.md` when it exists.
- Read relevant decisions under `docs/adr/`.
- If either is absent, proceed silently. Domain-document producer skills create them when terminology or architectural decisions are resolved.

## Vocabulary

Use the domain terminology defined in `CONTEXT.md` in issue titles, implementation plans, tests, and code. Avoid synonyms that the glossary explicitly rejects.

If required terminology is missing, reconsider whether new language is necessary or record the gap for a domain-document session.

## Architecture decisions

Surface any conflict with an existing ADR explicitly rather than silently overriding it.
